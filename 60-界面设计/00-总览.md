# 界面设计规范总览

> 适用范围：全端 UI ｜ 维护人：待定 ｜ 最后更新：2026-09-04

## 核心思路（2026 行业做法）
1. 选型优先：先用成熟组件库/设计系统（Web: Tailwind + shadcn/ui；小程序: TDesign/uni-ui；App: Material 3 / RN Paper），默认值即规范。
2. Token 文件为唯一事实源：品牌覆盖值放在设计 Token 配置文件 tokens.json（Figma Tokens Studio / W3C 兼容），不写在 Markdown 里。
3. 生成各端变量：由 tokens.json 生成 Web CSS 变量、小程序 app.wxss 变量、App 主题。
4. 仅当自建设计系统时才用完整规范；否则只覆盖少量品牌 token。

## 结构
- 10-设计Token规范.md：token 文件的结构/命名/分层/生成/Figma 同步（先读）
- 20-色彩系统.md：语义色名定义（取值在 tokens.json）
- 30-图标系统.md：图标来源/命名/尺寸
- 40-页面模板.md：列表/详情/表单/弹窗标准结构
- tokens/tokens.json：最小示例（复制到项目改品牌值）

## 用法
- 项目仓库放 design-tokens/tokens.json（或 src/styles/tokens.json），生成物提交入库。
- Codex 开发时：读 10-设计Token规范.md + 项目 tokens.json + 对应端组件库规范，禁止硬编码。
- 改样式 = 改 tokens.json → 重新生成 → 全端生效，不逐页改。
