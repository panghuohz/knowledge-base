# 项目 AGENTS.md 模板

> 用法：把本文件内容复制到「项目仓库根目录」并命名为 AGENTS.md（Codex 会自动读取），把 <...> 替换为实际值。一个项目一份，角色可随项目不同。

## 项目与角色
- 项目：<项目名，如 小蜗找房-用户端>
- 我的角色：<前端 / 后端 / 全栈 / 接口设计 / 架构 / 评审>
- 负责范围：<我负责的模块，如：搜索页、房源详情、消息中心>
- 技术栈：<如：微信小程序 + 云开发 / React Web + Spring Boot>
- 协作方：<单人 / 与谁协作>

### 标准格式示例
- 我的角色：前端开发（本仓库只负责 xxx 模块；后端另有其人 / 或也是我）
- 负责范围：搜索页、房源详情、消息中心
- 技术栈：微信小程序 + 云开发
- 协作方：后端同事 / 甲方自有团队 / 全栈一人

> 若本文件未填写上述四项：Codex 开工前应**主动询问**（我的角色 / 负责范围 / 技术栈 / 协作方），不得自行假设角色，也不得要求用户重复项目背景。

## 开发流程（每个需求一个小闭环）
1. 先读相关规范与现有代码/文档，不凭记忆假设。
2. 关键设计（新表、新接口、跨模块改动）先与用户确认再编码。
3. 实现后必须跑通验证命令（构建/测试/自测）——不自证不算完成。
4. 改动 Schema/API/前端约定时，同一提交内同步更新本项目文档与知识库对应文件。
5. 小步提交，git commit 用中文，如：feat: 新增房源搜索接口。

## 硬约束
- 不把客户资料、密钥、账号写入任何文档或提交。
- 知识库改动在 KnowledgeBase 仓库单独提交，不要混进本项目提交。
- 通用规范结论进知识库 01~70；本项目专属结论进 90-项目实例/<项目名>/；角色只出现在本文件或项目档案。
