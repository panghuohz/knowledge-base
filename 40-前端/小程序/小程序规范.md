# 小程序开发规范（建议初稿，待确认）

> 适用范围：微信 / 支付宝 / 抖音等小程序 ｜ 维护人：待定 ｜ 最后更新：2026-09-04

## 平台说明
- 默认以微信小程序为准；多端差异用条件编译或统一封装层，不散落 if 判断。
- 若使用云开发（技术栈示例：微信小程序 + 云开发），后端逻辑走云函数，接口层改为调用云函数。

## 依赖顺序
页面 → 接口 → Model → Store → Component → Page

## 目录
src/
  api/        接口/云函数封装
  models/     数据模型
  pages/      页面（含 pages.json / app.json 注册）
  components/ 自定义组件
  store/      状态
  hooks/      逻辑复用（或 behavior）
  utils/      工具
  constants/  常量
  styles/     公共样式
  subpackages/（可选）分包

## 规范要点
- 页面不直接发请求，统一走 api/ 层；数据先过 models 再进页面。
- 组件样式隔离：组件内样式不泄漏到页面（styleIsolation）。
- 尺寸用 rpx 适配；字体 / 图标与 60-界面设计 一致。
- 长列表 / 大数据避免一次性 setData 大对象；用分包控制主包体积。
- 生命周期：按需在 onLoad / onShow 拉数据，避免重复请求。
- 登录：wx.login → code2session（或云开发 openid）；用户授权按需申请。

## 发布
- 体验版 → 提审 → 正式版；涉及隐私接口需配置隐私协议。
- 线上问题回滚预案记录到项目档案。
